# Passive Detection Decoupling and Unified UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make General IDS, CVE Signature Detection, and Network Presence independently configurable and runnable, then expose them through one consistent three-panel UI while preserving all existing protocol logic and legacy URLs/API endpoints.

**Architecture:** Keep one global `NetworkPresenceTracker` instance for the existing web/API compatibility surface, but move packet tracking to the central packet dispatcher so it is no longer an implicit side effect of General IDS or a protocol plugin. Add an explicit `SignatureConfig` and runtime enable gate, initialize passive services independently, and keep General IDS writer/whitelist decisions fail-closed when IDS itself is disabled. Serve a new shared `passive_detection.html` asset from `/ids`, `/signatures`, and `/network-presence`; each URL selects its initial panel while all three panels use the same shell, style, enable switches, and bootstrap payload.

**Tech Stack:** ESP-IDF/FreeRTOS C++, cJSON, PSRAM allocators, PlatformIO asset generation, browser HTML/CSS/JavaScript, Python `unittest`/pytest host tests.

---

## Decisions and compatibility contract

1. The persisted configuration paths are:
   ~~~json
   {
     "ids": {
       "general": { "enabled": true },
       "signatures": { "enabled": true },
       "network_presence": { "enabled": true }
     }
   }
   ~~~
   Missing `ids.signatures.enabled` keeps the default `true`; existing `ids.general.enabled`, `ids.network_presence.enabled`, legacy `advanced_ids`, and legacy top-level `network_presence` remain readable.
2. The three runtime switches are independent. If General IDS is disabled while Network Presence is enabled, Network Presence continues to learn and report devices but does not authorize writers, suppress whitelist violations, or return an IDS bypass result. This is the fail-closed behavior for security decisions.
3. Signatures can be loaded, listed, uploaded, and reloaded while detection is disabled; disabling the switch suppresses packet matching and threat side effects but does not delete the signature database.
4. `/ids` is the canonical shared page. `/signatures` and `/network-presence` remain working aliases and open the corresponding panel. Existing API endpoints remain valid; a new atomic `/api/passive-detection/config` endpoint is added for the three switches.
5. The existing per-plugin `getNetworkPresenceTracker()` methods remain source-compatible for callers, but protocol plugins must not call `trackPacket()` for global presence. The central dispatcher performs exactly one presence update per captured packet.
